1) Components Overview

Data Sources

  • Defines the connection to your data backend.
  • Supported: SQL Server, Azure SQL DB, Oracle, Power BI Datasets, Excel, OData, etc.
  • Includes: server/URL, authentication (Windows/Basic/OAuth), connection properties (timeouts, catalog).

Tip: Name data sources clearly (e.g., SalesDB_Prod , ReportingWarehouse_2024 ).

Datasets

  • Represents the result of a query or table/view selection.
  • Based on SQL, table/view, stored procedure, embedded/shared dataset.
  • Dataset fields bind to report items (tables, textboxes, charts).

Best practice: Use aliases in complex queries; avoid SELECT * for performance and clarity.

Parameters

  • Built-in (page info) and custom (user-defined).
  • Used in SQL queries (WHERE), report filters, expressions (visibility/labels/titles).

Tip: Display friendly names with Parameters!X.Label .

UI Widgets

  • Table/Matrix: tabular display, grouping, sorting
  • List: repeating layout for custom design
  • Chart: bar/pie/line
  • Text Box: labels, values, expressions
  • Image: embedded/external
  • Subreport: embed another .RDL

Expressions:=Fields!Name.Value , =Parameters!Region.Value , =Globals!PageNumber

Page Header & Footer

  • Branding (logo, title), page info, date/time, disclaimers.

Subreports

  • Independent .RDL embedded into a parent report.
  • Use for reusable layouts or nested detail sections with different datasets.

Important: Size subreports explicitly and pass parameters as needed.

2) Steps to Build a Paginated Report

  1. Understand requirements: paper size, orientation, groupings, filters, totals, security.
  2. Register data sources: embedded/shared; test connection.
  3. Create datasets: query designer; preview; validate fields.
  4. Configure page size & margins: match target export (PDF/print).
  5. Add widgets: tables/lists/charts; set width/height/borders/padding/fonts.
  6. Grouping & sorting: groups, subtotals, headers; configure sort order.
  7. Expressions & formatting: conditional visibility, formatting (currency/date).
  8. Parameters & filters: bind to SQL and/or report filters; control visibility.
  9. Preview & test: page breaks, grouping, filters, parameter behavior.
  10. Save & export: PDF/Excel/Word/CSV/PPT/XML; deploy to Service/SSRS/Report Server.

Common Page Sizes

  • Letter Portrait: 8.5in x 11in
  • Letter Landscape: 11in x 8.5in
  • A4 Portrait: 8.27in x 11.69in

Avoid Blank Pages (PDF)

BodyWidth + LeftMargin + RightMargin  ≤  PageWidth

3) Additional Tips & Gotchas

  • Repeat headers: set RepeatOnNewPage on table/group headers.
  • Page breaks: add between groups; set KeepTogether = false for long groups.
  • Shared vs Embedded: shared sources/datasets help consistency across reports.
  • Performance: reduce heavy joins/subqueries; index filter/join columns; pull only needed columns.
  • Excel export: keep layout grid-aligned; avoid floating/overlapping objects.

4) Expression Language Quick Reference

1. Basic Field Display

Purpose Expression
Display a field value =Fields!Name.Value
Concatenate strings ="Customer: " & Fields!CustomerName.Value
Add numeric values =Fields!Price.Value + Fields!Tax.Value
Round to 2 decimals =Round(Fields!Amount.Value, 2)
Line break ="Name: " & Fields!Name.Value & vbCrLf & "Amount: " & Fields!Amount.Value

2. Formatting Numbers

Format Expression
Currency =FormatCurrency(Fields!Total.Value)
Currency (no decimals) =Format(Fields!Total.Value, "C0")
Number (2 decimals) =FormatNumber(Fields!Value.Value, 2)
Percent =FormatPercent(Fields!Score.Value)

3. Date & Time Formatting

Format Expression
Short date (MM/dd/yyyy) =Format(Fields!OrderDate.Value, "MM/dd/yyyy")
Long date/time =Format(Fields!OrderDate.Value, "F")
Year only =Year(Fields!OrderDate.Value)
Month name =Format(Fields!OrderDate.Value, "MMMM")

4. Conditional Logic (IIF / Switch)

Purpose Expression
Boolean condition =IIF(Fields!Status.Value = "Active", "✔", "✘")
Null check =IIF(IsNothing(Fields!EndDate.Value), "Ongoing", Fields!EndDate.Value)
Multiple conditions =Switch(Fields!Score.Value >= 90, "Excellent", Fields!Score.Value >= 75, "Good", True, "Needs Improvement")
Conditional color =IIF(Fields!Balance.Value < 0, "Red", "Black")

5. Visibility

Purpose Expression

6) Placeholders

What “Placeholder” Means in Report Builder

  • Textbox placeholder: a container that holds static text and/or an expression.
  • Value placeholders inside a textbox: when you mix text + expressions (the [<Expr>] areas).
  • Layout placeholders: empty cells/rectangles used to reserve space for later content.

Common Placeholder Patterns

Pattern Expression / How
Safe text when null =IIF(IsNothing(Fields!Notes.Value), "-", Fields!Notes.Value)
Show “(All)” when parameter blank =IIF(Len(Trim(Parameters!Region.Value & ""))=0, "(All)", Parameters!Region.Value)
Hide a textbox if empty Visibility → Hidden: =IIF(Len(Trim(Fields!Comment.Value & ""))=0, True, False)
“No data” placeholder message Textbox Hidden: =IIF(CountRows()=0, False, True)

Layout Helpers

  • Rectangle: use as a container to keep items together and aligned.
  • KeepTogether: helps avoid splitting a section across pages.
  • Padding over spaces: prefer padding settings instead of manual spacing.
  • Avoid overlaps: best for Excel export and predictable rendering.

7) Subreports (More Details)

When to Use Subreports

  • Reusable layouts shared across multiple reports.
  • Child section needs its own dataset / logic.
  • Nested details per group (customer → orders, department → employees).

Passing Parameters to the Subreport

Task Tip
Parent field → child parameter Subreport Properties → Parameters → Value: =Fields!CustomerId.Value
Parent parameter → child parameter Value: =Parameters!Region.Value
Multi-value parameter Pass the array directly; use provider-supported IN (@Param) patterns in child dataset.

Sizing & Page Break Behavior

  • Size explicitly: ensure subreport width fits usable page width.
  • CanGrow/CanShrink: control growth inside the child report to reduce unexpected expansion.
  • Performance: subreports can increase render time; keep child queries efficient.
  • PDF blank pages: subreport width beyond page width can create extra blank pages.

Common “No Data” Handling

  • In child report: show a “No rows returned” textbox based on CountRows() .
  • In parent report: optionally hide the subreport item when no relevant rows exist.
Visibility (Hidden) on Subreport item:
=IIF(CountRows("ParentGroupName")=0, True, False)
Tip: In your browser print dialog, enable “Background graphics” if you want the shaded headings and callouts to print.
