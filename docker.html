Part 1 — Docker Fundamentals

What is Docker?

Docker is a platform for building, packaging, running, and sharing applications using containers.

Instead of installing everything directly on a machine, Docker packages:

Application code
Runtime
Libraries
Dependencies
Configuration
into a portable unit.
Example:
docker run nginx

This downloads and runs the Nginx web server in a container.

Container

A container is a lightweight, isolated environment used to run an application.

A container has its own:

  • Filesystem
  • Processes
  • Network settings
  • Environment variables
  • Installed packages
  • Application

But it shares the host machine's operating system kernel.

Example:

docker run -it ubuntu bash

Linux Container

A Linux container uses Linux kernel features to isolate processes.

Key Linux technologies:

Namespaces
cgroups
Filesystem layers
Network isolation
Process isolation
Examples:
Ubuntu container
Alpine container
Debian container
CentOS container
All share the host kernel.

Is a Container an Operating System?

Not exactly.

A container looks like a small OS because you can run commands inside it:

docker run -it ubuntu bash
But it does not have:
Its own kernel
Full boot process
Virtual hardware
Better definition:

A container is an isolated user-space environment, not a complete operating system.

Container vs Virtual Machine

FeatureContainerVirtual Machine
KernelShares host kernelOwn kernel
SizeSmallLarge
StartupFastSlower
IsolationProcess-levelHardware/OS-level
Resource UsageLowHigher

Simple explanation:

VM = full computer inside your computer
Container = isolated application environment

Part 2 — Images and Building Containers

Image

An image is a read-only package used to create containers.

Mental model:

Image = Blueprint
Container = Running instance
Example:
docker pull nginx
docker run nginx
Multiple containers can be created from the same image:
docker run -d --name web1 nginx
docker run -d --name web2 nginx
docker run -d --name web3 nginx

Dockerfile

A Dockerfile contains instructions for building an image.

Example:

FROM nginx
COPY ./html /usr/share/nginx/html
Build:
docker build -t my-nginx .
Run:
docker run -p 8080:80 my-nginx
Flow:

Dockerfile

↓

Image

↓

Container

Layers

Images are built from layers.

Example:

FROM ubuntu:22.04
RUN apt-get update
RUN apt-get install -y curl
COPY app /app
Each major instruction creates a layer.
Image = Stack of Layers
Container = Image + Writable Layer

Writable Container Layer

Images are read-only.

When a container starts, Docker adds a writable layer on top.

Example:

  • Ubuntu layer
  • App layer
  • Config layer
  • Writable container layer

Changes made inside the container go into the writable layer.

Removing the container removes that layer.

Part 4 — Registries and Image Storage

Registry

A place where Docker images are stored.

Examples:

Docker Hub

GitHub Container Registry
Amazon ECR
Azure Container Registry
Google Artifact Registry

Docker Hub

Docker's public image registry.

Examples:

docker pull ubuntu
docker pull nginx
docker pull postgres
docker pull redis

Repository

A collection of image versions.

Examples:

nginx
ubuntu
postgres
redis

Tag

Represents a specific image version.

Examples:

nginx:1.27
postgres:16
ubuntu:22.04
If omitted:
latest
is assumed.

Part 5 — Storage

Volume

Persistent Docker-managed storage.

Example:

docker volume create pgdata
docker run \
-v pgdata:/var/lib/postgresql/data \
postgres
Use for:
Databases
Uploaded files
Application data
Persistent logs

Bind Mount

Maps a host folder into a container.

Example:

docker run \
-v "$(pwd)/html:/usr/share/nginx/html" \
nginx
Useful during development.

Part 6 — Networking

Network

Allows containers to communicate.

Example:

docker network create appnet
Containers:
docker run -d --name db --network appnet postgres
docker run -d --name app --network appnet myapp
Application connects using:
db
not
localhost

Port Mapping

Expose container ports to the host.

Example:

docker run -p 8080:80 nginx
Meaning:
Host Port      8080
Container Port 80
Access:
http://localhost:8080

Host

A host is simply a machine.

Could be:

Physical server
Virtual machine
Cloud VM
Laptop
Examples:
192.168.1.10
192.168.1.11
192.168.1.12

Localhost Confusion

Inside a container:

localhost = that container
On your machine:
localhost = your computer
Wrong:
DB_HOST=localhost
Correct in Compose:
DB_HOST=db

Part 7 — Docker Compose

What is Docker Compose?

Docker Compose runs multiple containers together using YAML.

Example:

services:
app:
build: .
db:
image: postgres:16
Run:
docker compose up -d

Service (Compose)

In Compose:

A service is a container definition.
Example:
services:
app:
image: myapp
db:
image: postgres
Compose creates containers from services.

Compose Project

Everything created by a Compose file:

Containers
Networks
Volumes
Example:
docker compose up -d
Creates:
myfolder-app-1
myfolder-db-1
myfolder_default
Custom project name:
docker compose -p myproject up -d

Docker Deployment Evolution

Level 1 — Single Container

docker run nginx
Host A
└── nginx

Level 2 — Multiple Containers

docker compose up
Host A
├── app
├── postgres
└── redis

Level 3 — Multiple Replicas

docker compose up --scale app=3
Host A
├── app1
├── app2
├── app3
└── postgres

Important:

All replicas run on the same host.
If Host A dies:
Everything dies
No clustering.
No failover.
No high availability.

Part 9 — Docker Swarm

What is Docker Swarm?

Docker's built-in clustering system.

Docker Compose = One machine
Docker Swarm   = Multiple machines

Create swarm:

docker swarm init

Level 4 — Cluster

Host A      Host B      Host C
app1        app2        app3

Node

In Swarm:

Host = Machine
Node = Machine participating in the Swarm
Types:

Manager Node

Worker Node

Manager Node

Controls the cluster.

Responsibilities:

  • Scheduling
  • Placement
  • Scaling
  • Updates
  • Health checks
  • Networking

Worker Node

Runs containers.

Example:

Worker 1
├── app1
└── app2
Worker 2
└── app3

Service (Swarm)

A Service is NOT a container.

It is a desired-state definition.

Example:

docker service create \
--name web \
--replicas 3 \
nginx
Meaning:
Keep 3 nginx containers running.

Replica

A replica is a copy of a service.

Example:

docker service create \
--name api \
--replicas 5 \
my-api
Creates:
api.1
api.2
api.3
api.4
api.5

Replicated Service

Normal service:

docker service create \
--replicas 5 \
nginx
Docker decides placement.

Global Service

One container per node.

docker service create \
--mode global \
fluentd

Result:

Host A -> fluentd
Host B -> fluentd
Host C -> fluentd
Used for:
Logging
Monitoring
Security agents

Placement Constraints

Force a service onto a node.

docker service create \
--constraint node.hostname==host2 \
nginx

Swarm Scaling

Example:

docker service create \
--name app \
--replicas 6 \
myapp
Possible placement:
Host A -> app1 app2
Host B -> app3 app4
Host C -> app5 app6

Are Replicas Always on Different Nodes?

No.

Swarm decides placement.

Possible:

Host A -> app1
Host A -> app2
or
Host A -> app1
Host B -> app2

Part 10 — High Availability Features

High Availability (HA)

Example:

Host A -> app1
Host B -> app2
Host C -> app3
Host B fails.
Swarm detects:
Desired = 3
Actual  = 2
Creates replacement automatically.

Self-Healing

Container crashes:

Desired = 3
Actual  = 2
Swarm starts another replica automatically.

Rolling Updates

Current:

api:v1
Update:
docker service update \
--image api:v2 \
api
Swarm replaces replicas gradually.

Part 11 — Traffic Management

Load Balancing

Traffic distributed across replicas.

User
|
Load Balancer
/ | \
app1 app2 app3

Routing Mesh

One of Swarm's best features.

Even if the container only exists on Host C:

Host A:8080
Host B:8080
Host C:8080
all still work.
Swarm forwards traffic internally.

Part 12 — Multi-Host Networking

Overlay Network

Network spanning multiple hosts.

Create:

docker network create \
--driver overlay \
appnet
Example:
Host A -> app1
Host B -> app2
Host C -> db
All communicate through:
appnet

Service Discovery

No need to know IP addresses.

Example:

DB_HOST=db
Docker DNS resolves:
db -> running service
even if IP changes.

Part 14 — Final Mental Model

One-Sentence Mental Model

Docker Image
= Blueprint

Docker Container
= Running isolated process

Docker Compose
= Many containers on ONE host

Docker Swarm Service
= Desired application definition

Docker Swarm Replica
= Copy of a service

Docker Swarm Node
= Machine in cluster

Docker Swarm Cluster
= Multiple Docker hosts managed together

Docker Swarm Load Balancer
= Distributes traffic

Docker Swarm Scheduler
= Decides placement

Docker Swarm Overlay Network
= Network across hosts

Docker Swarm Routing Mesh

= Any node can receive traffic and forward it
