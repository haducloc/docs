Access VBA X Framework Cheatsheet

Build scalable Access front-end apps that connect to remote SQL databases using ADO. Access is the UI layer; business logic and data access live in VBA modules/classes.

  • Access is the UI layer only for forms and reports.
  • Business logic and data access live in VBA modules/classes.
  • Database storage is a remote SQL database : SQL Server, MySQL, PostgreSQL, Oracle, etc.
  • Framework files start with X , for example XInputState , XStateCollection , and XAdoUtil .
  • App-specific files do not start with X , for example Ticket_MainForm and Ticket_EditForm .

Part 2 — Standard Form Pattern

For each database table, create a main search form, a datasheet subform, and an edit form.

For each table, create three forms:
  • Table_MainForm
  • Table_Datasheet
  • Table_EditForm
Example for the Ticket table: Ticket_MainForm , Ticket_Datasheet , and Ticket_EditForm .
2.1

Table_MainForm — Single Form Search Screen

Topic Rules / Flow
Typical UI
  • Top section: search controls such as txt... , cbo... , and chk... .
  • Bottom section: embedded Table_Datasheet subform.
  • Optional action button: btnAddNew .
Form_Load
  • Call ConfigCustomForm Me .
  • Call the search routine to load initial data.
Search routine
  1. Read search controls into XInputState .
  2. Add them to XStateCollection .
  3. If invalid, bind an empty recordset.
  4. If valid, run ADO search, apply sort, and bind to the datasheet subform.
2.2

Table_Datasheet — Datasheet Subform Only

Topic Rules
Design rules
  • Set DefaultView = Datasheet .
  • Add controls for each query field, such as textbox or checkbox controls.
  • No labels are required.
  • For each displayed field, set:
    • Control Source — field name from SQL.
    • Datasheet Caption — display caption in the grid.
Runtime rules
  • Let XDatasheetDelegate handle sort, double-click, and error plumbing.
  • Implement only:
    • ReloadOnParentOnSort(sortByAdo As String)
    • OpenEditForm(selectedRow As Object)
2.3

Table_EditForm — Single Form Add/Edit/Delete Screen

Topic Rules / Flow
Design rules
  • Set DefaultView = Single Form .
  • Add controls freely: labels, textboxes, combo boxes, check boxes, and buttons.
  • Naming convention:
    • txtName , txtDescription , chkIsDone , cboTypeID
    • btnSave , btnDelete
Form_Load
  • Call ConfigCustomForm Me .
  • Initialize dropdowns.
  • Parse primary key from OpenArgs .
  • Switch UI between add mode and edit mode.
  • Load the row if editing.
btnSave_Click
  • Convert controls to XInputState .
  • Validate via XStateCollection .
  • Map values to a dictionary and call InsertRowAdo or UpdateRowAdo .
btnDelete_Click Confirm with the user, then call DeleteRowAdo .
Form_Close Close the connection and refresh the parent main form.

Part 3 — Core Framework Concepts

Reusable building blocks for input parsing, validation, ADO commands, CRUD operations, and form behavior.

3.1

XInputState — One Control to One Typed State

Field Meaning
FieldName Database field name.
ValueType Data type such as int, string, bool, date, etc.
Value Converted value or Null .
IsValid Conversion and required-field validation result.
ErrorMessage Human-readable validation message.
Create typed states using helpers in XInputUtil :
  • GetString , GetCode
  • GetInt2 , GetInt4 , GetInt8 , GetByte , GetUByte
  • GetBool
  • GetDate , GetTime , GetDateTime
  • GetFloat , GetDouble , GetDecimal
Example 
Dim stName As XInputState

' GetXXX(ctrl, fieldName, required)
Set stName = GetString(Me.txtName, "Name", True)

If Not stName.IsValid Then
    MsgBox stName.ErrorMessage
End If
3.2

XStateCollection — Validate Many Controls Together

Capability Benefit
AllValid Aggregated validation for multiple states.
ToErrorString Centralized error display.
ToValuesDict Easy database payload creation using a dictionary.
Common Flow 
Dim states As XStateCollection: Set states = New XStateCollection
states.AddStates stName, stDescription, stIsDone

If Not states.AllValid Then
    MsgBox states.ToErrorString
    Exit Sub
End If

Dim values As Object
Set values = states.ToValuesDict
3.3

XAdoUtil — Parameterized ADO Command Helpers

Area Helpers
Core helpers
  • CreateCommandAdo(cn, sql)
  • ExecuteQueryAdo(cmd, disconnect=True)
  • ExecuteUpdateAdo(cmd)
Typed parameters
  • ParamByteAdo , ParamUByteAdo
  • ParamInt2Ado , ParamInt4Ado , ParamInt8Ado
  • ParamBoolAdo
  • ParamDateAdo , ParamTimeAdo , ParamDateTimeAdo
  • ParamVarcharAdo , ParamCharAdo
  • ParamLikeAdo , etc.
These helpers keep SQL parameterized and DB-provider-aware.
3.4

XAdoCrud — Generic Insert, Update, Delete, and Select by PK

Main APIs Notes
  • InsertRowAdo
  • UpdateRowAdo
  • DeleteRowAdo
  • GetRowByPkAdo
  • ExistsByPkAdo
 Pass fieldsCsv , typesCsv , and a values dictionary, often from XStateCollection.ToValuesDict . The framework builds SQL and appends typed parameters in the correct order.
3.5

XFormUtil + XDatasheetDelegate

Component Responsibilities
XFormUtil
  • ConfigCustomForm — Single Form settings.
  • ConfigCustomDatasheet — Datasheet settings.
  • TryOpenForm — prevent duplicate edit forms.
  • TryCallForm — call a public method on a loaded form.
XDatasheetDelegate
  • Datasheet sorting handoff to ADO recordset.
  • Double-click row to open edit form.
  • Datasheet filter/sort edge cases.

Part 4 — Ticket Sample Walkthrough

Example flow showing how the framework pieces work together in a Ticket module.

4.1

Connection Setup — App_DbConnection

  • Configure provider, server, and database in GetDbConString .
  • Use GetConnection(ByRef cn) to lazily create or open a cached ADODB connection.
  • Reuse this pattern in all forms and modules.
4.2

Main Search Form — Ticket_MainForm

SearchTickets Flow
  • Read search controls: GetInt4(Me.txtTicketID) , GetString(Me.txtName) .
  • Validate with XStateCollection .
  • If invalid, use CreateEmptyRsAdo .
  • If valid, call SearchTicketAdo(GetConn(), ...) .
  • Apply sort using BuildRsSortByAdo .
  • Bind result to Me.Ticket_Datasheet.Form.Recordset .
Me.Ticket_Datasheet.Form.Recordset
4.3

Search SQL Module — Ticket_Ado

  • Uses one parameterized query.
  • Uses optional filters with the (? IS NULL OR ...) pattern.
  • Uses ParamInt4Ado and ParamLikeAdo .
  • Returns a disconnected recordset via ExecuteQueryAdo(cmd, True) .
4.4

Datasheet Form — Ticket_Datasheet

Thin glue code only. The delegate handles events.
  • OpenEditForm reads selected TicketID .
  • Opens Ticket_EditForm with OpenArgs .
4.5

Edit Form — Ticket_EditForm

Action Behavior
Mode Determines add/edit mode from OpenArgs .
Dropdowns Loads options from SQL via ExecuteDropdownOptionsSqlAdo and XDropdownOptions.ToValueList .
Save Builds states with helpers such as GetString , GetBool , GetInt4 , and GetDate . Then validates and inserts/updates via XAdoCrud .
Delete Builds a primary-key dictionary, then calls DeleteRowAdo .
Close Calls Ticket_MainForm.RefreshTickets .

Part 5 — Creating a New CRUD Module

Repeat the same pattern for each new table: main form, datasheet form, edit form, and ADO search module.

5.1

Checklist

Step What to do
Create forms
  • YourTable_MainForm
  • YourTable_Datasheet
  • YourTable_EditForm
Design datasheet Map controls to query columns via Control Source , set Datasheet Caption , and keep it subform-only.
Design edit form Add inputs and action buttons. Use clear names such as txt... , cbo... , chk... , and btn... .
Create search SQL module YourTable_Ado : write a parameterized query and return a disconnected recordset.
MainForm logic Call ConfigCustomForm , collect search states, validate, and bind the recordset to the datasheet subform.
Datasheet glue Add delegate hooks; implement ReloadOnParentOnSort and OpenEditForm .
EditForm logic Parse OpenArgs primary key; load by primary key; save via InsertRowAdo / UpdateRowAdo ; delete via DeleteRowAdo ; refresh parent after close TryCallForm "YourTable_MainForm", "Refresh...".

Part 6 — Beginner Tips

Simple practices that keep Access VBA front-end code clean, reliable, and consistent.

6.1

Best Practices

  • Always use Option Explicit .
  • Prefer framework parsing methods such as GetInt4 and GetDate over manual conversion.
  • Always validate all input states before database write operations.
  • Keep SQL parameterized. Never string-concatenate user input into SQL.
  • Keep datasheet forms thin; put business logic in modules or parent forms.
  • Reuse X* framework modules instead of copy-pasting helpers.
  • Close objects such as Recordset and Connection in form close events.
