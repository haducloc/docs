1) Power BI Core Concepts (Big Picture)

Term What it is Beginner explanation When you use it
Power BI Desktop Authoring tool App to build reports on your computer Always (starting point)
Power BI Service Cloud service Website where reports & dashboards live Sharing, dashboards
Workspace Container Folder for reports, dashboards, datasets Team collaboration
Dataset Data model Cleaned, modeled data (tables + relationships) Base of all reports
Report Multi-page visuals Interactive pages with charts & tables Analysis & exploration
Dashboard Single-page view Pins from reports (read-only) High-level monitoring
You create multiple reports, then pin key visuals—such as charts, KPI cards, tables, and maps—as tiles into a single dashboard to provide a consolidated, high-level view. You can also pin entire report pages as live tiles (interactive), while most other visuals appear as static tiles that refresh with the data.

Key idea: Dataset → Report → Dashboard

2) Data Sources (Where Data Comes From)

Data Source Type Examples Use case Notes
Files Excel, CSV, TXT, PDF Small/medium data Best for beginners
Databases SQL Server, Oracle, MySQL Large structured data Common enterprise source
Cloud Services SharePoint, OneDrive, Salesforce Online systems Often supports auto-refresh
Web APIs, Web URLs External/live data May need cleaning and careful refresh
Azure Azure SQL, Data Lake Big data More advanced setups

3) Dataset & Data Modeling

Concept Meaning Beginner tip
Table Rows & columns of data Like Excel sheets
Column Field Used for charts and slicers
Row Record One transaction/event
Relationship Link between tables Use star schema (facts in center)
Fact Table Measurable data Sales, Orders, Amounts
Dimension Table Descriptive/Category data Date, Customer, Product
Calculated Column Column using DAX Row-level logic (use sparingly)
Measure Dynamic calculation Preferred for KPIs/totals

4) Charts & When to Use What

Fast Chart Picker

What question are you answering? Use this chart
Compare categories Bar / Column
Trend over time Line / Area
Parts of a whole Pie / Donut / Treemap
Single KPI Card / KPI
Detail records Table / Matrix
Actual vs target KPI / Gauge
Relationship (correlation) Scatter
Geography Map
Hierarchy Matrix / Treemap

Rule of Thumb

  • If your data has time → use line/column .
  • If your data has categories → use bar .
  • If you need exact numbers → use table/matrix .
  • If it’s share of total → use treemap or pie (≤5) .
Chart Best for When to use Avoid when
Bar Comparing categories Sales by product/category; long labels Too many categories (over ~15)
Column Comparison or time buckets Monthly totals; yearly comparison Very long category names (use bar)
Line Trends over time Revenue over months/years; multiple series (few) Too many lines (messy)
Area Volume over time Emphasize magnitude/cumulative feel Precise comparison needed
Pie / Donut Parts of whole (simple) Only when ≤ 5 categories and story is simple Many slices; precision required
Treemap Parts of whole (many) Contribution by category/subcategory Time trends
Table Exact values Detail pages, exports, record lists Trend storytelling
Matrix Hierarchy & drill Category → product breakdown; drill-down Simple totals only
Card Single KPI Total sales, total tickets, average handle time When context is needed
KPI Performance vs target Show value + trend + goal status When no target exists
Gauge Progress vs target Simple “how close are we?” indicator Overuse (takes space)
Scatter Relationship Spend vs sales; correlation detection Totals-only stories
Map Geography Sales by state/county/region Geography not meaningful

6) Filters & Parameters

7) Buttons & Interactions

Button Type Typical action
Page Navigation Move between report pages
Bookmark Save a view state (filters/visibility)
Drill-through Go to detail page with context
Reset Filters Clear slicers back to default
URL Open a webpage or document link

8) Report vs Dashboard

Feature Report Dashboard
Pages Multiple Single page
Data Source One dataset Can pin from multiple datasets
Interactivity High Limited (pinned tiles)
Editable Yes (Desktop/Service) No (tiles are pinned views)
Best for Analysis Monitoring KPIs

Shortcut: Reports = explore. Dashboards = watch.

9) Refresh & Performance

Concept Explanation
Import Mode Data stored in Power BI for fast visuals
DirectQuery Queries run live against the source database
Scheduled Refresh Automatic updates at set times in Service
Incremental Refresh Refresh only new/changed data (better for big datasets)
Gateway Required to refresh on-prem data sources in the cloud

10) Beginner Dashboard Layout Template

Section What to put there
Header Title + logo + last refresh time
KPIs Cards: Total Sales, Profit, Orders, SLA
Trends Line/column: trend over time
Breakdown Bar/treemap: top categories, top contributors
Details Table/matrix: drillable details
Filters Slicers on the left or top (keep few)

11) Common Beginner Mistakes (And Better Choices)

Mistake Better choice
Pie chart with 10 slices Treemap or bar chart
Too many visuals on one page Focus on KPIs + 2–4 supporting visuals
Using tables for trends Line or column chart
Gauge everywhere KPI visual or card + target indicator
Confusing time vs category axes Separate: trend chart for time, bar for categories
Tip: In your browser print dialog, enable “Background graphics” if you want the shaded headings and callouts to print.
